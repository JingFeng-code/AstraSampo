## 2. W1（`ux/w1-notes-export`）

### W1-a　控制字元檔名會讓後端回 500（建議，強烈）

審核時實測：檔名含 `\x00` 回「500 Internal Server Error」（未處理的例外），含換行、Tab、`\x1f` 等回 500 並顯示作業系統的「Invalid argument」。前端的 `markdownFilename()` 會先清掉這些字元，所以一般操作遇不到；但動工文件規定「檔名在後端重新清理」，後端自己要擋。

做法：
1. `_export_name()` 先移除 `[\x00-\x1f\x7f]`，再做原有的清理。
2. `_write_export` 的例外處理同時接住 `ValueError`，不要漏出未處理的 500。

驗收：`"a\x00b"`、`"line1\nline2"`、`"\x1f\x07bell"` 都回 200，檔名不含控制字元，且仍在目標資料夾內。測試加進 `test_notes_export.py` 的敵意檔名清單。

### W1-b　「下載」資料夾位置寫死（建議）

現在是 `Path.home() / "Downloads"`。Windows 使用者可以把「下載」搬到別的磁碟或 OneDrive，這時程式會在使用者目錄另外建立一個 `Downloads` 資料夾，使用者在檔案總管的「下載」裡找不到檔案。

做法：Windows 上用 Known Folder API 取得「下載」的真實位置（`SHGetKnownFolderPath`，`FOLDERID_Downloads`，可用 `ctypes`），失敗或非 Windows 才退回 `Path.home() / "Downloads"`。測試用 patch 取代整個取路徑函式即可，不要在測試裡呼叫真的 API。

### W1-c　存檔路徑只停 4.2 秒（建議）

成功的 toast 只顯示 4.2 秒，長路徑來不及讀，也不能複製。這正是原本使用者抱怨的「不知道存在哪裡」。

做法：存檔成功後，在筆記面板的按鈕下方保留一行「最後存檔：<完整路徑>」，文字可選取，直到下一次存檔或關閉面板。失敗不用保留（toast 已足夠）。

### W1-d　`exports` 資料夾沒有被 gitignore（建議）

開發模式下「下載」不能寫時會存到專案根目錄的 `exports/`，目前不在 `.gitignore`，會變成未追蹤檔案。把 `exports/` 加進 `.gitignore`。

## 3. W2（`ux/w2-deck-tabs`）

### W2-a　在「總結」分頁按快捷鍵會操作看不到的卡片（建議，強烈）

`App.jsx` 的鍵盤處理對左右鍵與 `N` 不知道目前在哪個分頁。在「總結」分頁按右鍵，卡片索引會悄悄改變並讓影片跳到另一張卡的時間（維持「一律暫停」的行為），按 `N` 會把看不到的那張卡收進筆記。

做法二選一，寫進回報你選了哪個：
- 把分頁狀態往上提到 `App`，在「總結」分頁時快捷鍵不作用；
- 或讓 `CardDeck` 在「總結」分頁時通知 `App`（例如 callback 或 ref）。

驗收：在「總結」分頁按左右鍵、`N`，卡片索引與筆記都不變。

### W2-b　窄版出現兩組「重點」分頁（建議）

寬度 375 時，上層已有「重點／字幕／章節」，卡片區裡又有「重點／總結」，兩個「重點」意思不同。把卡片區裡的分頁改名為「卡片」與「總結」（`deck.tabCards`，繁中與英文都要改），並確認 `deck-overview.test.mjs` 裡有關文字的斷言同步更新。

### W2-c　總結條列幾乎不會有連結（說明即可）

現在要「正規化後與卡片標題完全相同」才可點。真實模型的總結條列是長句，卡片標題限 20 字，幾乎永遠對不上，所以這個功能在實際使用上等於沒有。這符合動工文件（「對不上就維持文字，不要硬配」），**不用改**；但回報與 PR 說明請如實寫「預期多數情況沒有連結」，不要拿相同文字的假資料當成效果證明。

## 4. W3（`ux/w3-all-notes`）——退回

### W3-a　必修：「下載全部重點」會丟掉使用者寫的想法

重現（審核時用真正的 `useCards` 與 `createNoteMarkdown` 實測）：
1. 收進第一張卡，在筆記裡寫下「這段可以套用到目前的專案」。
2. 按「下載全部重點」。
3. 匯出的 Markdown 沒有這句話（輸出 `includes(...) === false`）。

原因：`handleExportAllNotes` 只用 `cardsHook.allClips()`，它每次用卡片重建，`note` 一律是空字串，沒有和已收進筆記的項目合併。

這是動工文件沒寫清楚的地方，不是你違規，但必須修。

做法：
- 匯出全部時，以 `cardIndex` 對應：已收進筆記的卡片用**筆記裡那一份**（保留 `note` 以及之後可能新增的欄位），沒收的才用卡片重建。
- 合併邏輯放進 `utils/clips.js` 當成純函式（例如 `mergeForExport(existingClips, builtClips)`），不要寫在元件裡。

測試（必須在修改前會失敗）：
- 純函式測試：已收且有備註的項目，合併後備註仍在；未收的項目有內容；順序依時間。
- 端到端的資料測試：沿用我審核時用的方式，用 `react-dom/server` 渲染一個呼叫 `useCards` 的測試元件，再丟進 `createNoteMarkdown`，斷言輸出含備註。

### W3-b　必修：筆記清單沒有限高，動作按鈕被推到最底

`.clip-list` 沒有最大高度。收了 31 則後，「下載」與「清空筆記」被推到面板最底，要捲過 31 個輸入框才找得到；這正是使用者抱怨的「要一直往下滑」。

做法二選一：
- 清單設最大高度（例如 `max-height: 40vh`）並在清單內部捲動；
- 或把動作列固定在面板底部（`position: sticky; bottom: 0`，要有背景色，避免和清單內容重疊）。

驗收：
- 收進 31 則後，「下載 Markdown 筆記」「下載全部重點」「清空筆記」不需要捲動整個面板就看得到。
- 寬度 375、768、1280 各附一張截圖，**截圖要用 31 則的狀態**，不要只截 6 則。

### W3-c　建議：兩個「下載」按鈕的名字太像

「下載 Markdown 筆記」和「下載全部重點」只差幾個字，使用者之前就抱怨過名字相近的按鈕容易點錯。建議改成能一眼看出差別的名稱，例如「下載已收的筆記」與「下載總結＋全部重點」（繁中與英文都要改），並同步更新測試。

### W3-d　基底說明

W3 疊在 W1 上。PR 要等 W1 合併後再開，或目標設為 W1 的分支，回報裡請寫明。

## 5. W4（`ux/w4-note-filename`）——合併方式要改

W4 本身邏輯沒問題（三種情況的狀態機與測試都對）。問題在合併：

W4 與 W1、W3 在 `frontend/src/App.jsx` 有**兩處**衝突（回報寫的是「一行」，實際是兩處）：
1. 匯入列：`notes-export.js` 的匯入要和 `note-filename.js` 的匯入並存。
2. `<NotesPanel …>` 那一行：W1／W3 加了 `onExportAll`、`onClipAll`、`onClear`、`onCopy`、`cardCount`，W4 把 `setFilename` 換成 `changeFilename`。

**危險**：如果解衝突時取了其中一邊，會遺失 `setFilename={changeFilename}`。這時所有測試仍然會通過（我審核時確認過），但使用者手動改的檔名會被標題蓋掉。

要做的事：
1. 把 W4 **rebase 到 W1、W3 之後**（先 W1、再 W3，最後 W4），自己解衝突。
2. 新增一條測試：讀 `App.jsx` 原始碼，斷言 `<NotesPanel` 那一行同時含 `setFilename={changeFilename}` 與 `onExportAll=`。
3. 回報時貼出 rebase 後的 `git log --oneline` 與解衝突的做法。
