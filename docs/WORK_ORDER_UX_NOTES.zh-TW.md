## W1　修好「下載 Markdown 筆記」

### 現象

桌面版（Windows 免安裝版）在筆記面板按「下載 Markdown 筆記」沒有任何反應，使用者不知道有沒有存、存在哪裡。

### 現況

`frontend/src/App.jsx` 的 `handleExportNotes()` 用 Blob 加 `<a download>` 觸發下載。這在一般瀏覽器可用。桌面版是 Tauri 2 + WebView2，`desktop/src-tauri/` 沒有任何下載處理，也沒有對話框外掛。**這是推測的原因，還沒有在桌面版上確認。**

### 要做的事

1. **先重現並記錄**：在桌面版按下按鈕，記下實際發生的事（完全沒反應／有下載但不知道位置／被擋下）。寫進 PR 說明。沒有桌面版建置環境就寫明「未能重現，依程式推測」。
2. **後端新增 `POST /notes/export`**（放在 `backend/app/api/notes.py`）：
   - 請求：`{ "filename": 字串, "markdown": 字串 }`。
   - 只接受這台電腦的請求：沿用 `app/api/local_video.py` 的 `on_this_computer()`，不是就回 403。
   - `markdown` 上限 2 MB，超過回 413。
   - 檔名在後端重新清理（可沿用 `_safe_name()`），一律加 `.md`，只取最後一段，不接受路徑。
   - 存到使用者的「下載」資料夾下的 `AstraTube` 子資料夾（`Path.home() / "Downloads" / "AstraTube"`）。該位置不能寫入時，改存到程式資料夾下的 `exports`，並在回應裡說明。
   - **不覆蓋既有檔案**：同名時加 ` (2)`、` (3)`。
   - 用 `_ensure_within()` 同樣的做法確認最後的路徑在目標資料夾內。
   - 回應：`{ "saved_to": 完整路徑 }`。
   - 錯誤訊息走 `app/core/messages.py`，繁中英文都要有。
3. **前端**：
   - 桌面版（`getDesktopConnection()` 有值）呼叫新端點；一般瀏覽器維持現在的 Blob 下載。
   - 成功後用現有的 toast 顯示「已存到：<路徑>」；失敗顯示看得懂的原因。**任何情況都要有回饋**。
   - 筆記面板加一個「複製 Markdown」按鈕（`navigator.clipboard.writeText`），當作存檔失敗時的退路；複製成功或失敗也要有 toast。
4. 產生 Markdown 的函式（`frontend/src/utils/notes-export.js`）保持是唯一來源，前後端不要各寫一份格式。

### 驗收條件

- [ ] 桌面版按下按鈕後，畫面出現存檔路徑，檔案確實存在且內容正確（UTF-8，中文不亂碼）。
- [ ] 連按兩次產生兩個檔案，第一個沒被覆蓋。
- [ ] 檔名含 `..\`、`/`、`:`、`*` 或超長字串時，檔案仍只會出現在目標資料夾內。
- [ ] 非本機來源的請求回 403。
- [ ] 一般瀏覽器（開發模式）仍可下載。
- [ ] 沒有筆記內容時按鈕是停用的（現有行為，不能壞）。

### 測試

- 後端 `backend/tests/test_notes_export.py`：正常存檔、同名不覆蓋、路徑跳脫被擋、超過大小、非本機被拒。用暫存資料夾，不要寫到真的下載資料夾。
- 前端 `frontend/tests/notes-export.test.mjs`（已有同類測試就擴充）：桌面版走端點、瀏覽器走 Blob、兩種結果都有 toast。

## W2　「總結」不再擋在重點上方

### 現象

「總結」固定在重點區最上方。每次切換重點，重點區會捲回最上面，使用者看到的是總結，要再往下滑才看得到剛切換的那張卡。31 張卡就要滑 31 次。

### 現況

`frontend/src/components/CardDeck.jsx`：

- `deck-overview` 區塊排在 `deck-head` 和導覽列之前。
- `useEffect(()=>{ if(deckRef.current) deckRef.current.scrollTop=0 },[index])` 在每次換卡時把重點區捲到最上面。

### 要做的事

1. 重點區的標題列下方加兩個分頁：「重點」和「總結」。預設「重點」。
2. 「重點」分頁：只有導覽列和卡片，**不顯示總結**。
3. 「總結」分頁：顯示總結段落與條列。每一條如果對得上某張卡，就讓它可以點，點了切到「重點」分頁並跳到那張卡；對不上就只是文字，不要硬配。
4. 沒有總結內容時不顯示「總結」分頁。
5. 換卡時仍捲到重點區最上方（這時最上方就是卡片本身）。
6. 記住使用者上次停在哪個分頁（`localStorage`，讀寫都包 try/catch）。換一支影片時回到「重點」。
7. 0 張卡的情況（`deck-empty`）維持現狀，直接顯示總結。
8. 分頁要能用鍵盤操作，使用 `role="tablist"`／`role="tab"`／`aria-selected`。左右方向鍵目前用來切換卡片，分頁不要搶這兩個鍵。

### 驗收條件

- [ ] 在「重點」分頁連續切換 5 張卡，每次卡片標題都在可視範圍內，不需要捲動。
- [ ] 「總結」分頁看得到完整總結。
- [ ] 重新整理頁面後分頁選擇還在；分析另一支影片後回到「重點」。
- [ ] 視窗寬度 375、768、1280 三種都不會出現橫向捲軸。
- [ ] 舊的工作階段（沒有 `overview` 欄位）不會出錯。

### 測試

`frontend/tests/deck-overview.test.mjs`：沒有總結時不顯示分頁、預設是重點、換影片會重設。

## W3　一鍵匯總全部重點

### 現象

要把重點收進筆記只能一張一張按。使用者想直接拿到整份重點。

### 要做的事

1. 筆記面板加「全部重點收進筆記」：把還沒收的卡片依原順序全部加入，已收的不重複。完成後 toast 顯示加了幾則。
   - 在 `frontend/src/hooks/useCards.js` 加 `clipAll()`，重用 `clipCard()` 組資料的邏輯，不要複製一份。
   - `clip.id` 目前用 `Date.now() + '-' + i`，一次加多筆時要確保不重複。
2. 筆記面板加「下載全部重點」：**不需要先收進筆記**，直接匯出「總結＋全部卡片＋隨手筆記」。走 W1 的同一條存檔路徑。
3. `createNoteMarkdown()` 增加可選的 `overview` 參數，有值時在最前面輸出「## 總結」。
4. 匯出時重點依影片時間排序（沒有時間的排最後，維持原順序）。
5. 筆記面板加「清空筆記」，要再確認一次才清（做法參考 `WatchAlong.jsx` 的放棄確認：同一個位置換成「確定清空？」加兩個按鈕，不要用 `window.confirm`）。
6. 按鈕變多之後要分主次：主要按鈕只留一個（有 Obsidian 時是「存入 Obsidian」，沒有時是「下載 Markdown 筆記」），其他用次要樣式。

### 驗收條件

- [ ] 31 張卡按一次「全部重點收進筆記」，筆記顯示 31 則，再按一次仍是 31 則。
- [ ] 沒有收任何重點時，「下載全部重點」仍可用，檔案含總結與全部卡片。
- [ ] 匯出的 Markdown 裡，模型輸出的內容不會破壞格式（標題內的換行會被壓成一行，現有 `oneLine()` 的行為要保留）。
- [ ] 「清空筆記」要按兩次才會清。

### 測試

擴充 `frontend/tests/` 裡筆記匯出的測試：`overview` 段落、排序、`clipAll` 不重複。

## W4　筆記檔名殘留上一支影片的標題

### 現象

筆記面板的檔名欄位顯示的是上一支影片的標題。截圖中目前的影片是「AI 代理時代的軟體工程品質」，欄位卻是「AI 大模型與程式設計師轉型的觀念基礎」。使用者照著存，檔名就是錯的。

### 現況

`frontend/src/App.jsx`：

```
useEffect(()=>{ if(result?.title) setFilename(f=>f||result.title) },[result?.title])
```

只有欄位是空的才會填。欄位值又存在 `localStorage`，所以第二支影片開始就一直是舊標題。

### 要做的事

1. 分析出新的影片時，檔名改成新標題。
2. 使用者手動改過檔名的話，在**同一支影片**內保留他改的值。
3. 欄位加上看得見的標籤「檔名」，現在只有 placeholder，有值時看不出這是什麼欄位。

### 驗收條件

- [ ] 連續分析兩支不同影片，檔名跟著變。
- [ ] 手動改檔名後切換卡片、收合面板，檔名不變。
- [ ] 重新整理頁面後檔名仍對應目前這支影片。

### 測試

把「要不要換檔名」抽成純函式（放 `frontend/src/utils/`），用 `node:test` 測三種情況：新影片、同影片已手改、同影片未改。

## W5　標題列被截斷、浮動按鈕蓋住卡片

### 現象

- 模型名稱顯示成「Groq/qwen/qwen3.8-27b / 13…」，來源顯示成「陪看…」，看不到完整內容。
- 右下角的「筆記」浮動按鈕蓋在卡片內容上。

### 要做的事

1. 標題列空間不夠時改成兩行：第一行標題，第二行是模型、來源、張數、進階工具。不要截斷到看不懂；真的放不下才截斷，並且滑鼠移上去或鍵盤聚焦時看得到完整文字。
2. 來源標籤（例如「陪看模式」）字數少，不應該被截斷。
3. 確認重點區底部留白足夠，捲到最底時卡片的按鈕不會被「筆記」「問模型」兩個浮動按鈕蓋住。寬度 375、768、1280 都要檢查。

### 驗收條件

- [ ] 三種寬度下，來源標籤都完整顯示。
- [ ] 捲到最底時，「收進筆記」「深入解析」兩個按鈕完全沒被蓋住。
- [ ] 沒有橫向捲軸。

### 測試

版面問題以截圖為準：PR 說明附三種寬度的修改前後截圖。

## W6　切換卡片時的播放行為（已決定，不用做）

使用者在 2026-11-17 決定：**切換卡片一律暫停**，也就是維持 `feat/ollama-cloud-and-ux` 目前的行為。

- YouTube：切換卡片時跳到該時間並暫停。**不要改** `frontend/public/player/youtube-host.js` 裡 `play=false` 時呼叫 `pauseVideo()` 的做法。
- Bilibili：切換卡片時播放器會重新載入並停在該時間、不自動播放，效果等同暫停。維持現狀。
- 按卡片上的時間按鈕（▶）仍然是跳到該時間並播放。

做 W2（分頁）時要注意：從「總結」分頁點某一條跳到對應的卡片，行為要和切換卡片一致，也就是暫停。

## 4. 審核時會檢查的事

- 每個驗收條件有沒有對應的測試或截圖。
- 測試在修改前是否會失敗（測試要真的測到行為，不是只確認程式碼裡有某段文字）。
- 有沒有改到範圍外的檔案或行為。
- 繁中與英文字串是否都有，介面上有沒有寫死的文字。
- 後端寫檔的路徑檢查是否能被 `..`、絕對路徑、超長檔名繞過。
- `localStorage` 的讀寫是否都有 try/catch。
- PR 上自動審查的留言是否都處理或回覆了。
